# ADR-0005: LLM Support and Light Mode

## Status

Accepted

## Context

KodeHold must support multiple LLM providers to avoid vendor lock-in and to enable second opinions (see ADR-0006). Ollama is available as a local provider for private inference. Users bring their own model via OpenCode's global configuration — KodeHold does not mandate a specific model.

Key forces:
- The user's default OpenCode model is the primary LLM (e.g. deepseek-v4-flash, gpt-4, etc.)
- Ollama should be available as an optional local provider for users who want private inference
- Light mode should give users an option to run on smaller local LLMs with >= 32k context
- OpenCode provides the LLM abstraction layer via `@ai-sdk/openai-compatible`

## Decision

### Provider Architecture

```
KodeHold → OpenCode → User's default model (primary)
                     → Ollama (optional local provider)
                     → OpenAI-compatible API (secondary)
```

All LLM communication goes through OpenCode's provider interface. No direct LLM calls. This ensures:
- Provider swapping without code changes — the user's global OpenCode config determines the default
- Consistent tool-use and message format
- Built-in retry, error handling, and streaming

### Model Configuration

KodeHold does not configure a default model in `opencode.json`. The user's global OpenCode model is used. Each team subagent has no model override in its frontmatter — all teams inherit the same default model from the user's OpenCode configuration.

Users who want Ollama can configure it in their OpenCode provider settings. The Ollama provider definition in `opencode.json` makes it available as an option without forcing its use.

### Light Mode (32k Context)

Light mode is an optional execution mode designed for users who want to run KodeHold on a local LLM with a context window of at least 32k tokens. It is NOT auto-detected — it must be explicitly activated.

When activated, light mode applies:

1. **Prompt Compression**: All prompts use the minimal template set. No explanatory text, no chain-of-thought examples.
2. **RTK Mandatory**: All file and git output goes through RTK compact mode — no exceptions.
3. **ICM Summaries**: Context is loaded from ICM summaries, not full memories. Full text is retrieved only on demand.
4. **Chunked Processing**: Files > 100 lines are processed in chunks. Each chunk is summarized before the next is loaded.
5. **Token Budget**: A hard 28k token budget per operation (leaving 4k for response). Operations exceeding the budget are split.
6. **No Redundancy**: No repeated context. Each message contains only new or changed information.
7. **Collapsed Teams**: Reviewers and Testers roles may be collapsed into a single "Quality" team to reduce orchestration overhead.
8. **English Only**: All responses in English. Token savings of ~15% vs Danish (or other non-English languages).

### Activation

Light mode is activated by setting the environment variable `KODEHOLD_LIGHT=1`. It is NOT auto-detected — the user chooses when to enable it.

## Consequences

- Positive: Users bring their own model — no vendor lock-in, no KodeHold-imposed model choice
- Positive: Light mode gives users a path to run on local LLMs with >= 32k context
- Positive: Ollama provider is available for those who want it, invisible to those who don't
- Negative: Light mode reduces output quality — summaries lose detail
- Negative: Collapsed teams in light mode violate separation of concerns principle
- Neutral: Provider abstraction via OpenCode means adding a new provider is config-only

## Implementation Phases

### Fase 2b — Model Recommendations

Adds a **"Recommended Models (llmfit)"** card to the Settings → Local Models tab that displays hardware-aware model recommendations generated by `llmfit recommend --json`.

**Backend — `GET /api/tools/recommendations`** (`workspaces/deepresearch/src/deepresearch/web/server.py`):

- New endpoint at line 1391 that runs `llmfit recommend --json` as a subprocess (15s timeout).
- If `llmfit` is not installed or not found, returns `{ "available": false }` with a descriptive message.
- On success, parses the JSON output, sorts the models by `score` descending, and returns the top 10 entries plus system metadata (`{ "available": true, "models": [...], "system": {...} }`).
- Handles edge cases: `shutil.which("llmfit")` check before execution, `subprocess.TimeoutExpired` and `FileNotFoundError` exceptions.

**Frontend — API client** (`workspaces/deepresearch/src/deepresearch/web/static/js/api.js`):

- New `export async function fetchModelRecommendations()` that fetches `/api/tools/recommendations` and returns the parsed JSON (or `{ available: false }` on HTTP error).

**Frontend — Settings UI** (`workspaces/deepresearch/src/deepresearch/web/static/js/views/settings.js`):

- `loadModelRecommendations()` (line 208) fetches data via `fetchModelRecommendations()` and renders a table with columns: **Score** (color-coded badge: green ≥90, amber ≥70, red <70), **Model Name**, **Category**, **Fit** (ideal/good/suboptimal badge), **Speed** (tok/s), **Context** (token count), and **Use Case**.
- Called from two places: at the end of `loadHardwareInfo()` (line 197) and directly from `loadSettingsView()` (line 529), ensuring recommendations load both on the hardware info tab and the full settings view.

**HTML** (`workspaces/deepresearch/src/deepresearch/web/dashboard.html`):

- A "Recommended Models (llmfit)" card with a `llmfitRecStatus` status badge and `modelRecommendations` container, placed after the hardware info section in the Local Models tab.

**Dependency**: Requires the `llmfit` CLI tool to be installed (install command: `curl -fsSL https://llmfit.axjns.dev/install.sh | sh -s -- --local`). When absent, the UI shows a helpful install prompt.

### Fase 2c — Ollama Install via Web UI

Adds one-click **Ollama installation** from the Settings → Local Models tab with live SSE streaming logs. Implements the install UI outlined in `workspaces/deepresearch/docs/adr/ADR-0005-auto-install-and-discover-local-llm-backends.md` § *Web UI Installation (live log tail)*.

**Backend — `GET /api/local-backends/ollama/status`** (`workspaces/deepresearch/src/deepresearch/web/server.py`, line 1427):

- Checks if `ollama` binary is on `PATH` via `shutil.which()`.
- If installed, runs `ollama --version` to retrieve the version string.
- Probes `http://localhost:11434/api/tags` with a 2-second timeout to determine if the Ollama service is running.
- Returns `{ "installed": bool, "running": bool, "version": str | null }`.

**Backend — `POST /api/local-backends/ollama/install`** (same file, line 1461):

- SSE streaming endpoint (`EventSourceResponse` from `sse_starlette`).
- **Pre-check**: if `ollama` binary already exists, returns an immediate SSE `install_error` with message "Ollama is already installed".
- If not installed, spawns `asyncio.create_subprocess_exec("sh", "-c", "curl -fsSL https://ollama.com/install.sh | sh")` with stdout piped (stderr merged into stdout).
- Streams each line of output as an SSE event with a simple progress heuristic (starts at 10, increments by 3 per line, caps at 90).
- On process exit with `returncode == 0`: emits an `install_complete` event with `{ "status": "success", "version": "...", "path": "..." }`.
- On non-zero exit: emits `install_error` with the exit code.
- On exception: emits `install_error` with the exception message.
- If the HTTP client disconnects mid-stream, the subprocess is terminated.

**SSE event types**:

| Event | When | Payload |
|-------|------|---------|
| `install_log` | Every line of install output | `{ "step": "download"\|"install"\|"verify", "message": str, "progress": int }` |
| `install_complete` | Successful installation | `{ "status": "success", "version": str, "path": str }` |
| `install_error` | Any failure | `{ "status": "error", "message": str, "code": str }` |

**Frontend — API client** (`workspaces/deepresearch/src/deepresearch/web/static/js/api.js`, line 247):

- `export async function fetchOllamaStatus()` — fetches `GET /api/local-backends/ollama/status`, returns parsed JSON (falls back to `{ installed: false, running: false }` on HTTP error).
- `export function getOllamaInstallURL()` — returns `'/api/local-backends/ollama/install'` (the SSE endpoint URL).

**Frontend — Settings UI** (`workspaces/deepresearch/src/deepresearch/web/static/js/views/settings.js`, line 282):

- **State machine**:
  ```
  IDLE → INSTALLING → [SUCCESS | ERROR] → IDLE
    ↑                       ↓
    └───── RETRY ───────────┘
  ```
  Tracked by `let ollamaInstallState` variable (`'IDLE' | 'INSTALLING' | 'SUCCESS' | 'ERROR'`).

- `checkOllamaStatus()` (line 285): Calls `fetchOllamaStatus()`, updates the status badge text and the Install button state. Shows "✅ Installed vX.Y.Z" if installed/running, "❌ Not installed" otherwise. Called on view load and after successful installation (via polling).

- `window.installOllama()` (line 312): Guarded against double-invocation. Resets the log container, sets state to `INSTALLING`, creates an `EventSource` from `getOllamaInstallURL()`, and registers three event listeners:
  - `install_log` — Appends a formatted line to `#ollamaInstallOutput` with a dynamic progress icon (⬇ for early, ⏳ for mid, ✅ for late stages), timestamp-like step label, and message text. Auto-scrolls to bottom.
  - `install_complete` — Appends a green success line, sets state to `SUCCESS`, disables the button, closes the EventSource, starts a polling interval (`pollAfterCompletion`) that calls `fetchOllamaStatus()` every second until `installed === true` (up to 30 attempts), then refreshes the UI via `checkOllamaStatus()`.
  - `install_error` — Appends a red error line, adds a **Retry** button (`onclick="window.installOllama()"`), sets state to `ERROR`, re-enables the Install button.
  - `onerror` fallback — If connection closes while still in `INSTALLING` state, shows a warning and transitions to `ERROR`.

**HTML** (`workspaces/deepresearch/src/deepresearch/web/dashboard.html`):

- `<span id="ollamaStatus">` — status badge next to the "Local Models" heading.
- `<button id="installOllamaBtn">` — one-click Install button, calls `window.installOllama()`.
- `<div id="ollamaInstallLog">` — terminal-themed container (dark background, monospace font, max-height 300px, scrollable) wrapping `#ollamaInstallOutput`.
- Hidden by default (`class="hidden"`), shown when installation starts.
- Styled log-line classes: `.log-icon`, `.log-step`, `.log-msg`, `.log-success`, `.log-error`, `.log-retry`.

### Fase 2d — Local Backend Management

Adds full lifecycle management for local LLM backends: install, uninstall, start, stop, and model pull from the recommendations table — all with SSE streaming feedback.

**Backend — llmfit management** (`workspaces/deepresearch/src/deepresearch/web/server.py`):

- `POST /api/local-backends/llmfit/install` — SSE streaming endpoint that runs `curl -fsSL https://llmfit.axjns.dev/install.sh | sh -s -- --local`. Streams each line of output as SSE events (`install_log` / `install_complete` / `install_error`). On success returns version and path.
- `POST /api/local-backends/llmfit/uninstall` — JSON endpoint that removes the llmfit binary (via `shutil.which` → `os.remove`). Returns `{ "status": "success" }` or `{ "status": "error", "message": "..." }`.

**Backend — Ollama service management** (same file):

- `POST /api/local-backends/ollama/start` — Starts the Ollama service. Attempts `systemctl --user start ollama` first; falls back to spawning `ollama serve` as a background subprocess. Returns `{ "status": "success" }` or `{ "status": "error", "message": "..." }`.
- `POST /api/local-backends/ollama/stop` — Stops the Ollama service. Attempts `systemctl --user stop ollama` first; falls back to `pkill ollama`. Returns `{ "status": "success" }` or `{ "status": "error", "message": "..." }`.
- `POST /api/local-backends/ollama/uninstall` — SSE streaming endpoint that performs a multi-step uninstall: stop service → remove binary → remove systemd service file → remove Ollama data directory (~/.ollama) → verify removal. Streams progress events per step.
- `POST /api/local-backends/ollama/pull` — SSE streaming endpoint that runs `ollama pull <model_name>`. Streams each line of pull output with progress parsing. On completion, triggers an auto-refresh of the discovered models list.

**Frontend — Settings UI** (`workspaces/deepresearch/src/deepresearch/web/static/js/views/settings.js`):

- **Hardware section**: Install/Uninstall buttons for `llmfit` with SSE log display (same terminal-themed container pattern as Ollama install).
- **Auto-Discovered section**: Start/Stop/Uninstall buttons for Ollama, each triggering the corresponding endpoint. Uninstall shows a confirmation dialog before proceeding.
- **Model recommendations table**: A "Pull" button per model row (when `ollama_name` is available). Clicking starts the `ollama pull <model>` SSE stream in a log viewer. On success, the discovered models list auto-refreshes. If `gguf_sources` are available, a GGUF download link is also shown.

**HTML** (`workspaces/deepresearch/src/deepresearch/web/dashboard.html`):

- Buttons: `#installLlmfitBtn`, `#uninstallLlmfitBtn`, `#startOllamaBtn`, `#stopOllamaBtn`, `#uninstallOllamaBtn`
- Log containers: `#llmfitInstallLog`, `#ollamaUninstallLog`, `#ollamaPullLog`
- Model recommendation rows: dynamic "Pull" button and GGUF link per row.
